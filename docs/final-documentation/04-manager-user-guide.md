# راهنمای مدیر مستقیم

نقش مدیر مستقیم از EmployeeProfile دارای گزارش مستقیم در همان شرکت مشتق می‌شود؛ نقش مدیریتی مستقل عمومی ندارد. در حساب چندنقشی، scopeها طبق [سیاست مجوزدهی](../authorization-policy.md) اجتماع می‌شوند؛ این union دسترسی به داده محرمانه خارج از HR assignment نمی‌دهد.

## تیم و صف درخواست‌ها

۱. وارد شوید و «درخواست‌ها» را باز کنید. فهرست سمت سرور فقط رکوردهای شخصی، درخواست‌های دارای `manager_snapshot` شما و داده HR مجاز را می‌دهد.
۲. درخواست را بازبینی کنید: بازه، تعداد روز کاری، توضیح و جانشین (در صورت مجاز بودن) و وضعیت. برای درخواست محرمانه جزئیات خنثی می‌شود و manager مجاز به تصمیم آن نیست.
۳. برای درخواست `PENDING` واجد شرایط، «تأیید» را بزنید یا «رد» را انتخاب و دلیل رد را وارد کنید. رد بدون دلیل پذیرفته نیست. درخواست `ESCALATED` فقط HR تصمیم می‌گیرد.
۴. برای تعارض/دسترسی نامعتبر، درخواست را از صفحه بازخوانی کنید؛ تغییر مدیر جدید به‌تنهایی مجوز تصمیم روی درخواست قدیمی را منتقل نمی‌کند.
۵. در درخواست غیرمحرمانه‌ای که مجاز به مشاهده آن هستید، بخش «نظرها» امکان ثبت نظر متنی دارد؛ تاریخچه نظرها حذف/ویرایش‌پذیر نیست. برای درخواست محرمانه، مکاتبه فقط HR مجاز است.

در کد، اقدام return-for-correction جدا از `amend` ثبت نشده است؛ «ارجاع به HR» فقط برای HR در رابط دیده می‌شود. delegation مدیر/جانشین تصمیم‌گیر نیز در صفحه/endpoint مجزا پیدا نشد. پس فرآیند رسمی بازگرداندن به کارمند/تعیین delegation را فرض نکنید. برای اصلاح موردی با HR هماهنگ کنید.

## تقویم، پوشش و مانده

- «تقویم» با scope `team` فقط درخواست‌های `APPROVED` گزارش‌های مستقیم را می‌خواند و برای جزئیات حساس برچسب خنثی دارد. تقویم شخصی `me` وضعیت‌های `PENDING`, `ESCALATED`, `APPROVED` و `WITHDRAWAL_PENDING` را نیز برمی‌گرداند.
- «پوشش تیم» آمار روزانه تعداد غایبان/تعداد نیرو را بر اساس واحد گزارش می‌دهد؛ API بازه حداکثر ۹۳ روز را می‌پذیرد. این محاسبه فقط درخواست‌های `APPROVED` را در شمارش غایب می‌آورد.
- «مانده سهمیه» اجازه انتخاب کارمند را در UI نشان می‌دهد؛ انتخابگر Frontend فهرست `employees()` را می‌گیرد، اما server برای مدیر دامنه direct-report را اعمال می‌کند. اگر کارمند هدف 404/خارج از فهرست است، دسترسی را دور نزنید.
- مدیر گزارش‌های مدیریتی HR/Executive را نمی‌بیند؛ `reports` برای HR یا exec تعریف شده است.

## محدودیت‌ها

مدیر نمی‌تواند نوع محرمانه را تصمیم بگیرد، نقش اعطا کند، سهمیه اصلاح کند یا تنظیمات سیاست را تغییر دهد. دسترسی مستقیم به درخواست به snapshot مدیر زمان ثبت و شرکت وابسته است. مشاهده صفحه در UI تضمین دسترسی endpoint نیست و پاسخ `403/404` باید رعایت شود. delegation/جانشین مدیریتی و تقویم پوشش ظرفیت/حد مجاز staffing در UI فعلی پیاده‌سازی نشده‌اند.

## عیب‌یابی

اگر صف خالی است، با HR از ثبت‌بودن manager در EmployeeProfile و وضعیت `PENDING` درخواست اطمینان بگیرید. اگر تیم/تقویم خارج از شرکت ظاهر شد، داده را استفاده نکنید و موضوع را امنیتی گزارش کنید. اگر رد بدون دلیل ممکن نیست، رفتار مطابق اعتبارسنجی server است.
