# راهنمای فعلی مدیریت انواع مرخصی

این راهنما مرجع فعلی UI و API برای کاتالوگ سراسری LeaveType است. این کاتالوگ `company` ندارد و HR به‌واسطه‌ی scope شرکت، اختیار تغییر سراسری پیدا نمی‌کند.

## نقش‌ها و دسترسی

| عملیات | دسترسی |
|---|---|
| فهرست ناشناس | رد می‌شود؛ نشست معتبر لازم است |
| فهرست مدیر سامانه (`admin`) | همه انواع، شامل غیرفعال |
| فهرست HR دارای RoleAssignment فعال و منقضی‌نشده | انواع فعال، شامل محرمانه |
| فهرست کارمند/مدیر مستقیم | انواع فعال و قابل درخواست توسط کارمند |
| فهرست گزارش‌خوان ارشد (`exec`) | ممنوع |
| ایجاد، ویرایش، فعال‌سازی، غیرفعال‌سازی | فقط Global Admin با `leave_type.global.manage` |
| حذف فیزیکی | پشتیبانی نمی‌شود |

`GET /api/v1/leave-types/` فقط خواندنی است. `POST` برای ایجاد و `PATCH /api/v1/leave-types/{id}/` برای ویرایش/تغییر وضعیت استفاده می‌شود. مجوز سمت سرور مرجع نهایی است؛ محدودیت فرم یا Route در مرورگر جایگزین آن نیست. برای HR، فهرست به شرکت خاص فیلتر نمی‌شود چون LeaveType سراسری است؛ هیچ فیلتر شرکت یا قابلیت Company-scoped در این API وجود ندارد.

## عملیات مدیر سامانه

۱. از «انواع مرخصی» نوع را ایجاد یا با «ویرایش» تغییر دهید.
۲. در هر ایجاد، ویرایش، فعال‌سازی و غیرفعال‌سازی، دلیل واقعی و Trim‌شده وارد کنید. طول مجاز ۱ تا ۵۰۰ نویسه است؛ دلیل در Audit ذخیره می‌شود.
۳. کلید ۲ تا ۳۲ نویسه، با حرف کوچک انگلیسی شروع می‌شود و فقط حروف کوچک، عدد و `_` می‌پذیرد. عنوان حداکثر ۱۲۸ نویسه است.
۴. خطای 400 ورودی، 403 مجوز، 409 تعارض/استفاده تاریخی و 429 محدودیت نرخ را بررسی کنید. فرم هنگام شکست عملیات حفظ می‌شود؛ دلیل را اصلاح یا اقدام را با توجه به پیام سرور دوباره انجام دهید.
۵. برای کنارگذاشتن نوع از «غیرفعال‌سازی» استفاده کنید. نوع غیرفعال در درخواست جدید قابل انتخاب نیست؛ درخواست‌ها و دفترکل قبلی حذف نمی‌شوند.

کلید و فیلدهای معنایی نوع (عنوان، اثر سهمیه، الزام تأیید/توضیح/جانشین، قابلیت درخواست کارمند و محرمانگی) پس از استفاده در درخواست یا دفترکل قابل تغییر نیستند؛ برای معنای جدید نوع دیگری ایجاد کنید. تغییر وضعیت فعال‌بودن، رنگ و ترتیب نمایش مجاز می‌ماند. این قید مانع بازنویسی معنای سوابق قدیمی می‌شود. Audit هر تغییر موفق شامل actor، عملیات، snapshot قبل/بعد، دلیل و زمان است؛ correlation ID در صورت ارائه ثبت می‌شود.

## راهنمای HR

HR فقط فهرست انواع فعال را می‌بیند و هیچ دکمه ایجاد، ویرایش، فعال‌سازی یا غیرفعال‌سازی ندارد. تلاش مستقیم برای نوشتن در API نیز 403 می‌گیرد. انواع مختص شرکت قابلیت جداگانه‌ای هستند و برای طراحی آن‌ها باید تصمیم محصول/مالک داده و مدل tenant-scoped تصویب شود؛ Global LeaveType را برای این منظور به HR واگذار نکنید.
